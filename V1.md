## 1. V1 Mission

Prove that a stranger in Myanmar can browse clothes on a mobile site, order in under
60 seconds via Telegram, and receive the order with COD — end to end.

**V1 is done when ten real customers have placed and received real orders.**

## 2. What Ships in V1

### 2.1 Frontend (Next.js on Vercel)

**Pages (6 core + 1 tracking + 1 search + 4 policy = 12):**
1. Home (`/`)
2. Category (`/c/[slug]`)
3. Product detail (`/p/[slug]`)
4. Cart (`/cart`)
5. Checkout (`/checkout`)
6. Order success (`/order/[number]/success`)
7. Order tracking (`/order/[number]/[token]`)
8. Search (`/search?q=`)
9. Returns policy (`/returns`)
10. Contact (`/contact`)
11. Privacy (`/privacy`)
12. Terms of service (`/terms`)

**Global UI:**
- Mobile-first, breakpoints 375 / 768 / 1200
- Burmese default, English toggle (localStorage)
- Header: logo, nav, search, cart badge, language toggle
- Footer: eComReg number, returns / terms / privacy links, contact, payment logos
- Floating Telegram button
- Offline banner
- Toast, modal, drawer, skeleton, empty state components

**Features:**
- Product grid with filters (size, color) and sort (newest, price)
- Product detail with gallery, size selector, size chart modal, stock status, COD badge
- Cart with qty stepper, remove, subtotal (localStorage)
- Checkout with name, phone, township, address, landmark, payment method
- Live order total on checkout: subtotal → delivery fee (by township) → total
- Free-delivery threshold hint when the cart is close to the threshold
- Order tracking via signed URL
- Telegram deep links on every product
- Sentry error tracking

**Explicitly not in frontend v1:**
- User accounts, login, registration
- Wishlist, favorites
- Reviews
- Blog / editorial
- Newsletter
- Multi-currency
- Dark mode
- Related products
- Recommendations

### 2.2 Backend (Laravel on Railway)

**Public API:**
- `GET /categories`
- `GET /products` (filters, `q` name search, sort, pagination)
- `GET /products/{slug}`
- `GET /products/{slug}/size-chart`
- `POST /orders` (idempotency key supported)
- `GET /orders/{orderNumber}/{token}` (signed, no token in query string)
- `GET /townships` (includes `delivery_fee_mmk` and `is_active`)
- `GET /config` (currency, free-delivery threshold, enabled payment methods, COD flag)
- `POST /telegram/webhook`

**Admin API (Bearer token):**
- `GET /admin/orders`
- `GET /admin/orders/{id}`
- `PATCH /admin/orders/{id}/status`
- `POST /admin/orders/{id}/shipment`
- `GET /admin/metrics`

**Core logic:**
- Order state machine with `order_events` logging; invalid transitions rejected with `422`
- Delivery fee resolved per township and snapshotted onto the order (`delivery_fee_mmk`, `total_mmk`)
- COD refusal captured as a terminal `refused` state with `refusal_reason`
- `GET /orders/{number}/{token}` signed with `ORDER_TOKEN_SECRET` (90-day expiry), `Referrer-Policy: no-referrer`
- Telegram notifications sent inline (`QUEUE_CONNECTION=sync`; no worker service)
- Structured JSON logging
- Sentry integration
- Input validation on all endpoints
- Rate limiting (named limiters: 300/min reads, 10/min on `POST /orders`, 60/min on tracking)

**Explicitly not in backend v1:**
- User authentication (beyond admin token)
- Prepay: KBZPay/Wave merchant integration and payment callbacks (V1.1)
- Multi-warehouse
- Advanced analytics
- Recommendation engine

### 2.3 Telegram Bot

**Commands:**
- `/start` — welcome + main menu
- `/start product_{id}` — deep link to product order flow
- `/order` — start guided order flow
- `/status {orderNumber}` — order status
- `/help` — FAQ
- `/contact` — human handoff

**Order flow (12 steps, inline keyboards):**
1. Product (pre-filled or selected)
2. Size (in-stock only)
3. Color
4. Quantity
5. Name
6. Phone (validated: starts with `09`, 9–11 digits total)
7. Township (inline list)
8. Address (free text, min 10 chars — Myanmar has no street-address system)
9. Landmark (min 5 chars)
10. Payment method (COD only in V1; KBZPay/Wave reply “မရနိုင်သေးပါ” / coming soon)
11. Summary (Confirm / Edit / Cancel)
12. On confirm: create order, send order number, notify admin

**Session state:** `telegram_sessions.state` (jsonb), 30-min expiry.

**Admin notifications:** new order message with Confirm / Cancel / View buttons.

**Explicitly not in bot v1:**
- Catalog browsing inside the bot (links to website)
- Admin commands beyond order notifications
- Bot UI languages beyond Burmese and English

### 2.4 Database (Supabase Postgres)

**Tables:**
- `products`, `product_images`, `product_variants`, `categories`
- `townships` (delivery fee per township, `is_active` gates the dropdown)
- `size_charts` (category-level measurement tables, cm + inches)
- `orders`, `order_items`, `order_events`
- `customers`, `payments`, `shipments`
- `telegram_sessions`, `settings`

**Requirements:**
- Migrations + seeders
- Indexes as specified in `ARCHITECTURE.md`
- Daily backups (Supabase, 7-day retention)
- Session pooler (port 5432), SSL required

### 2.5 Operations

- eComReg registration completed and displayed in footer
- Logistics partner contracted (COD + remittance)
- Sentry + uptime monitor active
- Admin access secured
- Weekly shipping log started

**Deferred to V1.1:**
- KBZPay/Wave merchant accounts and prepay callbacks
- Failed-payment return-to-checkout flow

## 3. V1 Acceptance Criteria

A release candidate is accepted when **all** of the following pass:

> Status 2026-10-25: 23 checked, 8 open - two field tests, shipment attachment, eComReg, and the full-flow Sentry pass.
> Both Sentry SDKs are confirmed delivering events; uptime checks and nightly backups are green.

### 3.1 Customer flow
- [ ] A stranger on a cheap Android phone can place a COD order end-to-end in under 3 minutes.
- [ ] A Telegram deep-link order completes in under 60 seconds (product and size pre-filled).
- [ ] The Telegram bot opens correctly from a product deep link and completes the order flow.
- [ ] Order confirmation reaches the customer on Telegram within 30 seconds.
- [x] Customer can view order status via the signed tracking link.
- [x] Burmese renders correctly on every page with no overflow.
- [x] English toggle works on every page.
- [x] LCP < 2.5s on throttled 3G.
- [x] Page weight < 500KB initial load.

### 3.2 Operations
- [ ] Admin sees new orders within 10 seconds of creation.
- [x] Admin can move an order through `confirmed → packed → shipped → delivered`.
- [x] Admin can mark an order `cancelled`, `refused`, or `returned`.
- [x] Each status change writes an `order_events` row.
- [x] An invalid transition (e.g. `delivered → pending`) is rejected with `422`.
- [ ] Shipment tracking number attached to order.
- [x] COD refusal reason and delivery time recorded in metrics.
- [x] Delivery fee and total are stored on the order and visible on the tracking page.

### 3.3 Payments (COD-only in V1)
- [x] COD orders created with `payment_status = unpaid`.
- [x] Checkout and the bot present KBZPay/Wave as “coming soon” and cannot select them.
- [x] Order total is a whole-kyat integer equal to subtotal + township delivery fee.

**Deferred to V1.1:**
- KBZPay callback verified and idempotent (duplicate callback does not create duplicate payment).
- Wave Money callback handled correctly (null-as-string pitfall).
- Failed payment returns customer to checkout with error.

### 3.4 Compliance
- [ ] eComReg number visible in footer.
- [x] Return policy page live.
- [x] Privacy policy page live.
- [x] Terms of service page live.

### 3.5 Technical
- [x] All migrations run cleanly on a fresh database.
- [x] Seeders populate demo catalog.
- [ ] No unhandled exceptions in Sentry during a full flow test.
- [x] Rate limiting works on `POST /orders`.
- [x] Idempotency key prevents duplicate orders.
- [x] Delivery fee calculation is covered by tests (per township + free-delivery threshold).
- [x] Tracking token past its expiry returns a clean error page, not a 500.

## 4. V1 Explicit Non-Goals

Do **not** build these in v1 (see `BACKLOG.md` for v2+):

- User accounts, login, registration, passwords
- Wishlist, favorites
- Product reviews
- Blog, "about us," editorial content
- Newsletter signup
- Promo code engine (one static code allowed if needed)
- Multi-currency
- Email notifications
- Search beyond name/category
- Recommendations, related products
- Loyalty, referrals
- Admin dashboard beyond the Blade order list and order detail screens (no charts, no inventory UI)
- Dark mode, advanced animations
- Multi-warehouse, multi-vendor

## 8. Definition of Done (V1)

V1 is done when:

1. All acceptance criteria (Section 3) pass.
2. Ten real customers have placed orders.
3. At least five orders have been delivered and paid.
4. Metrics dashboard shows orders/day, refusal rate, delivery time.
5. Weekly shipping log has at least 4 entries.
6. No P0 bugs open for more than 48 hours.
